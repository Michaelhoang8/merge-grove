Messages in transit

A message is an immutable snapshot captured when sent. Deliver it late, keep a copy for duplicate delivery, or drop it.

Why these states converge

Each set addition has a unique replica-local tag. Removing a label records only the tags that replica has observed. A concurrent addition with a different tag therefore survives. Once a tag is removed, an older snapshot cannot resurrect it. Tombstones remain for the lifetime of the scenario.

The PN counter stores separate nondecreasing positive and negative components for each replica. Merge takes each component's maximum; the visible value is the sum of positives minus the sum of negatives. Duplicate delivery never adds a counter component twice.

Set merge unions tagged additions and tombstones. Counter merge takes componentwise maxima. Both are commutative, associative, and idempotent. Replicas converge after their updates are delivered; permanent partitions or dropped updates can keep them apart. The status compares full internal states, not just currently visible labels.

This is a deterministic simulation, not a network service. Up to 200 actions and 40 queued snapshots are supported. Synchronization requires healed links and appends six send/deliver pairs. Old queued snapshots remain available. Resetting or undoing changes the simulated history, not a live distributed system.
